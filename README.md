# VOICEVOX Coding

Claude Code と Codex のイベントを VOICEVOX の音声で読み上げる、Windows 向けの常駐ツール。
応答が終わったとき、許可待ちで止まったとき、作業の途中経過を話しているときに、画面を見ていなくても状況が分かる。

読み上げる内容、声、用語辞書は、ブラウザで開く管理コンソールから設定する。
設定はデーモンが持っているので、変更するとその場で反映され、フック定義を書き換える必要はない。

---

## 動作要件

| 項目 | 内容 |
| --- | --- |
| OS | Windows |
| Node.js | 20 以上 |
| VOICEVOX | インストール済みであること。アプリを起動しておく必要はない |
| PowerShell 7 | セットアップとアンインストールのスクリプトが使う（[入手先](https://aka.ms/powershell)） |
| Claude Code / Codex | 読み上げたい方だけでよい |

VOICEVOX アプリは音声を作るための GUI であって、合成 API 自体は同梱のエンジン（`vv-engine\run.exe`）が持っている。
このツールはエンジンを直接起動するので、アプリを常駐させる必要はない。

npm パッケージへの依存はなく、Node の標準モジュールだけで動く。

## セットアップ

### 1. リポジトリを取得する

```bash
git clone https://github.com/ktysne/voicevox-coding.git
```

以降のコマンドは、取得したディレクトリの中で実行する。

### 2. フックを登録する

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -RegisterStartup
```

Claude Code の `settings.json` と Codex の `hooks.json` に、デーモンへ転送するだけのフックを登録する。
既存の設定はバックアップしたうえでマージするので、ほかのフックはそのまま残る。

| オプション | 効果 |
| --- | --- |
| `-RegisterStartup` | サインイン時にデーモンを自動起動し、タスクトレイに常駐させる |
| `-IncludeToolEvents` | ツール実行の前後も登録する。呼び出しのたびにプロセスが起動するので、必要なときだけ |
| `-SkipClaude` / `-SkipCodex` | 片方だけ登録する |

### 3. デーモンを起動する

```bash
npm run console
```

管理コンソールがブラウザで開く。
以後はタスクトレイのアイコン、または `http://127.0.0.1:7591/` からアクセスする。

起動時に VOICEVOX エンジンが動いていなければ、実行ファイルを自動検出して立ち上げる。

`-RegisterStartup` を付けていれば、次のサインイン以降は自動で起動する。
多重起動しても 2 つ目はポートの重複を検出して終了するので、自動起動と手動起動が競合することはない。

自動起動はリポジトリの場所を指して登録される。
取得したディレクトリを移動したり消したりした場合は、`scripts\install.ps1` を実行し直す。

### 4. Codex のフックを承認する

Codex は未承認のフックを実行しない。
`codex` を起動して `/hooks` から承認する。

Claude Code だけで使う場合、この手順は要らない。

### 5. 動作を確認する

```bash
npm run doctor
```

エンジン、デーモン、両方のフックの登録状態、Codex の信頼状態をまとめて点検する。
Codex Desktop 内のターミナルではなく、通常の PowerShell から実行する（Codex Desktop ではサンドボックス用の別の `CODEX_HOME` が使われるため）。

ここまで通れば、あとは Claude Code か Codex を普段どおり使うだけで読み上げが始まる。

## 更新

更新は次のコマンド 1 つで完了する。
事前に `git pull` を実行しておく必要はない。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\update.ps1
```

PowerShell のプロンプトから実行する。
エクスプローラからダブルクリックで実行すると、エラーが起きてもコンソール窓が閉じてしまい内容を確認できない。

リポジトリを最新化しただけでは、更新は反映されない。
デーモンが常駐プロセスとして旧コードのまま動き続け、フック定義とスタートアップ登録も `install.ps1` が生成した時点の内容のまま残るからである。

次の手順は `update.ps1` の内部処理であり、手動で行う必要はない。

1. `git pull --ff-only` でリポジトリを最新化する
2. 稼働中のデーモンを停止する
3. `install.ps1` を再実行し、フック定義とスタートアップ登録を作り直す
4. 停止したデーモンを起動し直す

スタートアップ登録の有無は自動で判定して引き継ぐ。
導入時に `-IncludeToolEvents` などのオプションを指定していた場合は、更新時にも同じオプションを付ける。
npm パッケージへの依存はないので、`npm install` は不要である。

停止トークンを取得できない場合（`runtime.json` を書き出さない版のデーモンからの初回更新など）は、本デーモンのプロセスだと確認したうえで自動的に停止して続行する。
この場合、エンジンなどの後始末は次回のデーモン起動時に行われる。
トークンを取得できているにもかかわらず停止 API でデーモンを止められない場合は、従来どおりスクリプトは中断してトレイの「終了」による停止を案内する。
本デーモンのプロセスだと確認できた場合に限り、`-Force` を付ければ強制終了して続行できる。

`update.ps1` を使わず手動で更新する場合は、`git pull` の後にトレイの「終了」でデーモンを止め、`install.ps1` を同じオプションで実行し直してから `npm run start` で起動する。

フック定義そのものが変わる更新では、Codex の再承認が必要になることがある。
更新後に `npm run doctor` を実行すると、承認状態も含めて点検できる。

## 日常の操作

### タスクトレイ

デーモンはタスクトレイに常駐する。
アイコンの色が状態を示す。

| 色 | 状態 |
| --- | --- |
| 緑 | 待機中 |
| 青 | 読み上げ中 |
| 灰 | 一時停止中 |
| 赤 | エンジン未接続 |

右クリックメニューから、管理コンソールを開く操作、発話のスキップ、全停止、読み上げの一時停止、エンジンの起動と停止、終了ができる。
ダブルクリックでも管理コンソールが開く。

「読み上げを一時停止」は会議中などに使う想定で、プロセス内だけの状態として持つ。
デーモンを再起動すると読み上げは有効に戻る（気づかないまま無音が続くのを避けるため）。

常駐させたくない場合は、管理コンソールの「タスクトレイに常駐する」を外すか、`node src/daemon/main.js --no-tray` で起動する。

### 管理コンソール

`http://127.0.0.1:7591/`

| タブ | 内容 |
| --- | --- |
| Claude Code / Codex | それぞれ独立した設定。話者、声の調整、読み上げるイベント、ツールの絞り込み、無視パターン、本文のどこを読むか、発話の重なり方 |
| 用語辞書 | 置換ルールと VOICEVOX ユーザー辞書。両ターゲット共通 |
| エンジン・詳細 | エンジンの起動と停止、自動起動、接続先、ポート、ログ、キャッシュ、トレイ常駐 |
| ログ | デーモンの動作ログ。読み上げを見送った理由は debug レベルに出る |

変更は入力するたびに自動保存され、即座に反映される。
デーモンの再起動が要るのは、ポートを変えたときだけ。

## 設定

### 読み上げるイベント

| イベント | Claude Code | Codex | 既定 |
| --- | :-: | :-: | --- |
| `Stop` 応答完了 | ○ | ○ | 本文を読む |
| `MessageDisplay` 途中経過 | ○ | — | 本文を読む |
| `Commentary` 途中経過 | — | ○ | 本文を読む |
| `Notification` 通知 | ○ | — | 定型文 |
| `PermissionRequest` 許可待ち | — | ○ | 定型文 |
| `PreToolUse` / `PostToolUse` | ○ | ○ | オフ |
| `UserPromptSubmit` | ○ | ○ | オフ |
| `SessionStart` / `SessionEnd` | ○ | ○ | オフ |
| `SubagentStop` | ○ | ○ | オフ |
| `PreCompact` | ○ | ○ | オフ |

イベントごとに「本文を読む」と「定型文」を切り替えられる。
定型文では `{tool_name}` などのプレースホルダが使える。

### 途中経過の読み上げ

ツールを動かしている合間の説明文（「まず実際に発火するか確かめます」のような進行の説明）も読み上げる。
応答の完了を待たずに何をしているか分かるので、既定で有効にしてある。

不要なら、管理コンソールの「読み上げるイベント」で `MessageDisplay` のチェックを外す。

Claude Code では `MessageDisplay` イベントを使う。
このイベントは 1 つのメッセージにつき、行のまとまりが確定するたびに何度も発火するため、断片のまま読むと文の途中で切れる。
そこでデーモン側でメッセージごとに溜め、最終の断片が届いた時点で 1 つの発話にまとめている。

使ううえでの注意点は 3 つ。

- キュー方針は「順番に並べて全部読む」にする。「差し替え」だと次の説明文が来るたびに前が切れて、断片しか聞こえない。既定は `enqueue`。
- 最後のメッセージは `MessageDisplay` と `Stop` の両方から届く。同じ内容なので `dedupeWindowSec`（既定 10 秒）で二重読みを防いでいる。
- 発火のたびにフッククライアントのプロセスが起動する。1 メッセージあたり数回から数十回になるが、`async: true` なので Claude Code の表示は待たされない。

Codex の標準フックには `MessageDisplay` に相当する途中経過のイベントがない。
そこでデーモンが公式の `codex app-server` API をローカルで起動し、Codex Desktop（source kind `vscode`）の `agentMessage` のうち `phase=commentary` を約 2 秒ごとに監視する。
監視を始めた時点で既にある途中経過は読まず、開始後に現れたものだけを `Commentary` として読む。

この機能には `codex` CLI が必要で、デーモンを起動する環境の `PATH` から `codex app-server` を実行できなければならない。
CLI がない場合や app-server API が一時的に失敗した場合も、デーモン本体とフック経由の読み上げは動作を続ける。
不要なら、管理コンソールの Codex タブにある「途中経過（Codex）」をオフにする。

### 読み上げない本文

「無視パターン」に正規表現を並べておくと、一致した本文は発話ごと飛ばす。
バックグラウンドタスクの実行ログのような、決まった文面を読ませたくないときに使う。

判定は整形前の本文に対する部分一致で、大文字小文字は区別する（区別したくないときは `[Bb]ackground` のように書く）。
既定は空なので、設定しなければ今までどおり全部読む。
解釈できない正規表現は読み上げ時に飛ばす。管理コンソールでは欄から離れた時点で理由が出る。

`(a+)+$` のように書き方次第で照合が事実上終わらない正規表現があり、デーモンは 1 スレッドで動くため、
素で実行すると読み上げどころか管理コンソールごと固まる。
そこで照合は時間制限付き（1 パターン 50 ミリ秒、1 回の判定で合計 200 ミリ秒）で走らせ、
間に合わなかったパターンは「一致しなかった」ものとして扱う。
黙り込むより読み上げるほうが安全なので、打ち切っても発話は止めない。

一度時間切れになったパターンは、次からは短い時間（5 ミリ秒）で試す。
毎回 50 ミリ秒を捨てずに済み、本文が短くて一瞬で終わるときは元どおり効く。

「プレビュー」の整形結果と試聴にも無視パターンが効くので、書いたパターンはその場で試せる。
声の調整に使う「試聴」ボタンは対象外（本文ではなく声を確かめるため）。

飛ばしたパターンは、その理由をログに warn で残す（同じ内容は設定を変えるまで 1 回だけ）。
「書いたのに効かない」ときはログタブを見る。

### 本文のどこを読むか

コードブロック、インラインコード、URL、ファイルパス、表について、それぞれ「読む」「定型語に置き換える」「飛ばす」を選べる。
見出し、箇条書き記号、Markdown 記号、絵文字、HTML タグ、thinking ブロックは、個別にオンオフできる。
文字数と文数の上限も設定できる（0 で無制限、つまり全文読み上げ）。

`MOVEFILE_REPLACE_EXISTING` のような大文字とアンダースコアで書かれた定数名は、そのままだと
1 文字ずつのスペル読みになって聞き取れない。既定では「movefile replace existing」のように
単語へ分けて読む。不要なら「定数名（FOO_BAR 形式）」を「そのまま読む」にする。
用語辞書の置換ルールは整形の後に適用されるため、定数名に固有の読みを与えたい場合は
変換後の表記（例: `movefile replace existing`）を対象に書く。

箇条書きは項目のあいだに無音の間が入る（既定 0.3 秒、0 で無効、上限 10 秒）。項目は句点で終わらないことが多く、
そのまま続けて読むと繋がった 1 文に聞こえるため。既存の設定にも既定値として入るので、間が要らなければ 0 にする。

間を入れると、読み上げは項目ごとに区切って合成される。そのぶん合成の回数と音声キャッシュのエントリが増え、
更新後の初回はキャッシュが効かない。項目数の多いリストでは、合成の回数が増えるぶん全体が長くなる
（間そのものに加えて、チャンクごとの無音も乗る）。用語辞書の置換ルールも項目ごとに当たるので、
`^` を使ったルールは各項目の先頭にも一致し、改行をまたぐルールは一致しなくなる。

整形結果のプレビューには間が現れない（読み上げるテキストには余計な文字を入れないため）。
効き具合は「読み上げてみる」で確かめる。

「プレビュー」に応答テキストを貼れば、実際に読み上げるテキストと音声をその場で確認できる。

### 用語辞書

2 層で誤読を直す。

- **置換ルール**：合成前にテキストを書き換える。長い表記から順に当たる。正規表現も使える。
- **VOICEVOX ユーザー辞書**：エンジンの形態素解析器に読みとアクセントを教える。活用形にも効くので、固有名詞はこちらが確実。読みは全角カタカナで書き、「エンジンに反映」で同期する。

### エンジンの扱い

| 設定 | 既定 | 内容 |
| --- | --- | --- |
| `engine.enginePath` | 自動検出 | 空欄なら起動中プロセス、レジストリ、既知のパスの順で探す |
| `engine.autoStart` | on | デーモンの起動時にエンジンも起動する |
| `engine.stopOnExit` | on | デーモンの終了時に、自分で起動したエンジンだけ止める |
| `engine.healthCheckSec` | 60 | 落ちていたら起動し直す間隔（秒） |
| `engine.useGpu` | off | 対応環境なら合成が速くなる |

VOICEVOX アプリを手動で開いている間は、そちらが立てたエンジンをそのまま使う。
アプリが立てたエンジンをこのツールが勝手に止めることはない（管理コンソールでも「エンジンを停止」が押せなくなる）。

## 運用

### 長い応答の読み上げ

本文は文の切れ目でチャンクに割って順に合成する。
最初の音が出るまでが短く、再生中に次のチャンクを先読みするので繋ぎも詰まる。

チャンクや次の発話が残っている間は、再生の完了後に短い無音をループして Windows の音声出力を保つ。
これがないと、次の音声の出だしが欠けることがある。

### 読み上げ中に次の応答が来たとき

挙動は「発話の重なり方」で決める。
既定は順番に並べて全部読む。
不要な発話が溜まりやすい用途では、差し替え（古い読み上げを止めて新しい方を読む）か、読み飛ばすへ変更できる。

管理コンソールの右上とタスクトレイから、現在の発話のスキップ、キューの全停止、読み上げの一時停止ができる。

### フックの所要時間

フッククライアントはデーモンに投げて終わるだけで、所要時間のほとんどは Node の起動時間が占める。
Claude Code は `async: true` で待たないが、Codex は同期実行なので、この時間だけターンの終了が遅れる。
ツール実行の前後を有効にすると 1 ツール呼び出しごとに乗るため、既定では登録していない。

### ログ

`%USERPROFILE%\.voicevox-coding\daemon.log`

読み上げなかった理由（`event-disabled`、`tool-filtered`、`duplicate` など）を見たいときは、ログの詳細度を `debug` にする。

### 設定ファイル

`%USERPROFILE%\.voicevox-coding\config.json`

直接編集しても、保存した時点でデーモンが読み込む。
壊れた JSON を書いた場合は退避されて、既定値で起動する。

## アンインストール

デーモンが動いている場合は、先にタスクトレイの「終了」で停止する。
アンインストールのスクリプトはフックの登録とスタートアップ登録を取り除くだけで、動作中のデーモンは止めない。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\uninstall.ps1
```

`-RemoveConfig` を付けると、設定とキャッシュも消す。
デーモンの動作中はログやキャッシュのファイルが使用中で消せないことがあるため、この点でも先に停止しておく。

## 構成

```
Claude Code hook ─┐
                  ├→ hook-client.js ─→ 常駐デーモン ─→ VOICEVOX ENGINE
Codex hook ───────┘   (stdin→POST)      ├ 設定の保持とホットリロード
                                        ├ 発話キュー（重なり制御、スキップ）
                                        ├ 読み上げ要素のフィルタ
                                        ├ 用語辞書（置換 + ENGINE ユーザー辞書）
                                        └ 管理コンソール（localhost の Web UI）
```

フック側にロジックを置かず、判断をすべてデーモンに寄せている。
理由は 3 つ。

1. Codex はフック定義のハッシュで信頼を管理する。定義を変えるたびに再承認が要るため、フックは薄いまま固定したい。
2. Codex は `async: true` のフックを読み込み時に破棄する（0.145 時点）。フック内で音声合成すると、その間 Codex のターンが止まる。合成をデーモンに追い出せば、フックはミリ秒で返せる。
3. 設定の変更を、プロセスの再起動なしで反映できる。

## 既知の注意点

- **デスクトップアプリでのフック発火**：公式ドキュメントでは全環境で同じイベントが発火するとされているが、Windows デスクトップアプリで `settings.json` の hooks が発火しないという報告がある。動かない場合はまず CLI で確認し、スクリプトの問題かアプリ側の挙動かを切り分ける。
- **Codex の async 非対応**：`async: true` を書くと `async hooks are not supported yet` として警告のみで破棄される。エラーにならないので気づきにくい。`npm run doctor` がこれを検出する。
- **Codex は `command` 先頭の実行ファイルを引用できない**：`"C:\Program Files\nodejs\node.exe" "script" codex` のように書くと起動に失敗し、`hook: Stop Failed` とだけ表示される。エラーの内容は出ないので静かに壊れる。引数側の引用は効くので、実行ファイルは PATH 上の `node` を素の名前で指定する（`node "script" codex`）。Claude Code はシェル経由なのでどちらでも動く。`npm run doctor` がこれを検出する。
- **Codex のフックの信頼**：フック定義を変更するとハッシュが変わり（`trustStatus` が `modified` になる）、再承認が必要になる。`/hooks` で個別にオフにしたものは、承認済みでも実行されない。
- **`.ps1` は UTF-8 BOM 付きで保存する**：Windows PowerShell 5.1 は BOM が無いと ANSI として読むため、日本語コメントが化けて構文エラーになる。`install.ps1` と `uninstall.ps1` は起動時に PowerShell 7 へ引き継ぐが、引き継ぐ前にパースされるので BOM は必須。
