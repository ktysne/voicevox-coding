## AUD-01 外部 Web ページからローカル API を操作できる

**重要度**：高

**どこで起きる**：[`src/daemon/server.js`](src/daemon/server.js#L139-L146) の HTTP 受付と、同ファイルの設定変更、再生制御、エンジン制御、終了 API で起きる。

**何が起きる**：利用者が悪意ある Web ページを開くだけで、デーモン停止、エンジン停止、読み上げ停止、設定変更を実行される可能性がある。

**何故起きる（根拠）**：状態変更前に `Origin`、CSRF トークン、`Content-Type` を検証しておらず、`text/plain` のクロスオリジン要求も JSON として処理する。

悪意ある `Origin` と `text/plain` を付けた検証では、`/api/config` の設定変更が受理され、`/api/shutdown` の終了コールバックも実行された。

**どう対応する**：状態変更 API に起動ごとの CSRF トークンを要求し、管理 UI、トレイ、フッククライアントだけがそのトークンを送れるようにする。

ブラウザ経由の API では、許可する `Origin` と JSON の `Content-Type` も副作用の実行前に検証する。

**なぜそう対応する**：CORS の応答ヘッダーだけでは要求の送信を止められず、サーバー側で信頼できる呼び出し元を識別する必要がある。

**どうなる**：通常のローカル操作を保ったまま、外部 Web ページからのドライブバイ操作を拒否できる。

## AUD-02 キャッシュ無効時も WAV ファイルが無制限に残る

**重要度**：中

**どこで起きる**：[`src/daemon/queue.js`](src/daemon/queue.js#L165-L188) の音声合成結果の保存処理で起きる。

**何が起きる**：`daemon.cacheEnabled` を `false` にしても、内容の異なる発話ごとに WAV ファイルが残り続け、ディスク使用量が増え続ける。

**何故起きる（根拠）**：キャッシュの有効、無効にかかわらず WAV を `CACHE_DIR` へ保存する一方、上限による削除はキャッシュ有効時だけ実行する。

**どう対応する**：キャッシュ無効時は発話専用の一時 WAV を作り、再生完了、スキップ、合成失敗のすべての経路で削除する。

**なぜそう対応する**：Windows の再生 API へ渡す短寿命ファイルは必要だが、再利用しない音声を永続キャッシュへ残す必要はない。

**どうなる**：キャッシュ無効設定が表示どおりに働き、長期運用でも WAV ファイルが蓄積しない。

## AUD-03 先読み合成の失敗で長い発話が無通知に途切れる

**重要度**：中

**どこで起きる**：[`src/daemon/queue.js`](src/daemon/queue.js#L238-L255) の次チャンク先読みと、同ファイルの発話終了処理で起きる。

**何が起きる**：長文の二つ目以降のチャンクで VOICEVOX ENGINE が停止またはタイムアウトすると、残りの発話が無言で打ち切られ、通常の合成失敗ログも残らない。

**何故起きる（根拠）**：先読み Promise の例外を `.catch(() => null)` で破棄し、次のループでは `null` を発話終了として扱う。

**どう対応する**：先読みの失敗を Promise の rejection のまま保持し、利用時に通常の合成エラー処理へ渡す。

意図的なスキップ後に限って、その rejection を抑止する。

**なぜそう対応する**：同じ ENGINE 障害を、通常合成と先読み合成で同じ失敗として扱う必要がある。

**どうなる**：発話が途中終了した場合でも、ログと `error` イベントから原因を確認できる。

## AUD-04 再生ワーカーの遅延応答が後続コマンドへ誤対応する

**重要度**：中

**どこで起きる**：[`src/daemon/player.js`](src/daemon/player.js#L82-L119) の標準出力処理と応答タイムアウトで起きる。

**何が起きる**：ある `PLAY`、`HOLD`、`STOP` が 10 秒でタイムアウトした後に遅れて応答すると、その応答が次のコマンドを完了させたものとして処理される。

以後は実処理と完了認識がずれ、音声の途中停止や残留再生につながる。

**何故起きる（根拠）**：プロトコルにコマンド ID がなく、受け取った応答を常に `pending.shift()` で先頭の待機処理へ割り当てる一方、タイムアウトした処理だけを配列から削除する。

**どう対応する**：タイムアウト時に再生ワーカーを終了し、その世代の待機処理をすべて失敗させてから新しいワーカーを起動する。

将来プロトコルを拡張する場合は、コマンドと応答へ同じ ID を付ける。

**なぜそう対応する**：現行ワーカーは実行中コマンドを取り消せないため、タイムアウト後も同じ FIFO 接続を使い続けることはできない。

**どうなる**：遅延応答が後続操作へ混入せず、再生状態とキュー状態の対応を保てる。

## AUD-05 辞書同期の重複または途中失敗で管理不能な単語が残る

**重要度**：中

**どこで起きる**：[`src/daemon/dictionary.js`](src/daemon/dictionary.js#L69-L126) の VOICEVOX ユーザー辞書同期で起きる。

**何が起きる**：同じ表記を複数登録した場合、ENGINE の辞書一覧取得が一時失敗した場合、複数語の同期が途中失敗した場合に、重複語または以後削除できない UUID が ENGINE 側へ残る。

**何故起きる（根拠）**：同じ `surface` を重複排除せず処理し、一覧取得失敗を空辞書として続行し、外部 API の変更が部分成功しても所有 UUID を全処理完了後に一度だけ保存する。

**どう対応する**：同期前に `surface` の重複を入力エラーとして扱い、辞書一覧を取得できなければ同期を中止する。

外部 API の成功ごとに所有状態を安全に記録するか、失敗時に今回の追加分を補償削除する。

**なぜそう対応する**：ENGINE の辞書 API はトランザクションではなく、ローカルの所有状態が遅れると再試行を冪等にできない。

**どうなる**：一時障害後に再試行しても同じ単語が増えず、このツールが追加した語を後から確実に更新または削除できる。

## AUD-06 自動保存のたびに設定画面のフォーカスが失われる

**重要度**：中

**どこで起きる**：[`src/ui/app.js`](src/ui/app.js#L88-L107) の自動保存、同ファイルの [`config` SSE ハンドラー](src/ui/app.js#L789-L794)、[`src/daemon/server.js`](src/daemon/server.js#L114-L116) の設定配信で起きる。

**何が起きる**：テキストまたは数値の入力を止めて約 500 ミリ秒後、自動保存に伴って表示中パネルが再生成され、入力欄のフォーカスとカーソル位置が失われる。

**何故起きる（根拠）**：`saveNow()` は要求送信前に `savePending` を `false` にし、サーバーは同じ保存を直ちに SSE で送り返す。

SSE 側は保存待ちでないと判断して `renderActivePanel()` を呼び、`replaceChildren()` で入力 DOM を置き換える。

**どう対応する**：受信設定が現在のローカル設定と同一なら再描画しない。

必要なら保存要求へクライアント ID またはリビジョンを付け、自分の保存通知を識別する。

**なぜそう対応する**：値が同じ自己通知に DOM の再生成は不要であり、外部編集だけを反映すればよい。

**どうなる**：自動保存を維持したまま、入力を一時停止して再開しても同じ欄で編集を続けられる。

## AUD-07 URL 後方の日本語本文が読み上げから消える

**重要度**：中

**どこで起きる**：[`src/daemon/textfilter.js`](src/daemon/textfilter.js#L8-L8) の URL 正規表現と、同ファイルの [URL 置換処理](src/daemon/textfilter.js#L47-L52) で起きる。

**何が起きる**：URL の直後に空白を置かず句点と日本語文を続けると、URL だけでなく後続文も「リンク」へ置き換わる。

**何故起きる（根拠）**：`https?:\/\/\S+` が空白までの全文字を URL とみなすため、日本語の句点と後続文も一致範囲に入る。

`詳細は https://example.com。次の文です。` を既定設定で処理すると、結果は `詳細は リンク` になった。

**どう対応する**：URL 末尾として扱わない日本語の句読点、閉じ括弧、引用符を一致範囲から外し、代表的な日本語文をテストへ追加する。

**なぜそう対応する**：日本語では URL と句点の間に空白を置かない表記が一般的であり、空白だけを境界にできない。

**どうなる**：URL を省略または置換しても、その後に続く説明文は読み上げに残る。

## AUD-08 空白または日本語を含むパスが不完全に短縮される

**重要度**：中

**どこで起きる**：[`src/daemon/textfilter.js`](src/daemon/textfilter.js#L23-L25) のファイルパス正規表現と、同ファイルの [パス置換処理](src/daemon/textfilter.js#L58-L73) で起きる。

**何が起きる**：Windows パスに日本語または空白があるとパス全体を認識できず、ディレクトリ断片とファイル名を混ぜた誤った文章を読み上げる。

**何故起きる（根拠）**：各パス要素を ASCII 中心の `\w` と少数の記号だけで定義し、空白と日本語を許可していない。

`C:\Users\山田\My Project\src\index.ts を更新` を既定設定で処理すると、`C:\Users\山田\My index.ts を更新` になった。

**どう対応する**：引用符または Markdown の区切りを考慮しつつ、Unicode と空白を含むパス要素を認識する。

日本語ユーザー名、`Program Files`、空白を含むリポジトリ名をテストへ追加する。

**なぜそう対応する**：Windows のユーザーディレクトリとインストール先では、空白と非 ASCII 文字が通常の入力として現れる。

**どうなる**：「ファイル名だけ読む」または「飛ばす」の設定が実際の Windows パスでも一貫して働く。

## AUD-09 Codex 監視の再接続でポーリングタイマーが増殖する

**重要度**：中

**どこで起きる**：[`src/daemon/codex-commentary-monitor.js`](src/daemon/codex-commentary-monitor.js#L136-L177) の初回走査、切断処理、再接続で起きる。

**何が起きる**：初回の `scan()` 中に `codex app-server` 接続が切れると、再接続後も古いポーリングタイマーが残り、切断を重ねるたびに走査頻度と RPC 負荷が増える。

デーモン停止時も最新のタイマーしか解除されない。

**何故起きる（根拠）**：切断処理が既存タイマーを解除して再接続を予約した後でも、古い `#connect()` は `await this.scan()` から戻ると接続世代を再確認せず、新しい `setInterval()` を作る。

FakeTransport で初回走査中に切断させる検証では、再接続後にポーリングタイマーが二本生成された。

**どう対応する**：`scan()` の直後にも `running` と `transport === this.transport` を確認してからタイマーを開始する。

タイマーを接続世代ごとに所有し、切断と終了時にその世代のタイマーを必ず解除する。

**なぜそう対応する**：非同期処理の前後で接続の所有権が変わり得るため、開始前の確認だけでは古い接続の後続処理を止められない。

**どうなる**：接続障害を繰り返しても設定した約 2 秒周期を保ち、不要な RPC とタイマーを残さない。

## AUD-10 日本語を含むパスではスタートアップ起動に失敗する

**重要度**：中

**どこで起きる**：[`scripts/install.ps1`](scripts/install.ps1#L242-L258) が生成する `start-daemon.vbs` で起きる。

**何が起きる**：Node.js またはリポジトリのパスに日本語が含まれる環境では、サインイン時に VBS が存在しない文字化けしたパスを起動しようとし、デーモンが常駐しない。

**何故起きる（根拠）**：PowerShell 7 の `Set-Content -Encoding UTF8` は BOM なし UTF-8 を書く一方、Windows Script Host はその VBS を ANSI として解釈する。

日本語の対象パスを埋め込んだ同形式の VBS を `cscript.exe` で実行すると文字化けした名前が使われ、UTF-16LE で保存した場合は正しい日本語名が使われた。

**どう対応する**：生成する VBS を `Set-Content -Encoding Unicode` により UTF-16LE で保存する。

インストールテストには日本語を含む一時パスからの起動確認を追加する。

**なぜそう対応する**：Windows Script Host が確実に文字コードを判別でき、埋め込んだ Windows パスを変更せず解釈できる形式が必要である。

**どうなる**：日本語のユーザー名またはフォルダー名を使う環境でも、サインイン時にデーモンが起動する。
