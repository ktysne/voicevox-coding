## 判断待ち

- PowerShell が使えない環境(Constrained Language Mode、AppLocker など)では、接続元の確認(#91、#92)も、エンジンの所有者の確認(#94)も、拒否する側に倒れる。そのため管理画面と、デーモン自身が起動していないエンジンは使えない。この扱いでよいかは未決である。

## 落とし穴

- 監査ではコードを実行していない。各 Issue の「何が起きる」は見込みで、再現は確かめていない。担当は、直す前に単体テストで現象を確かめる。
- 再現に別の OS ユーザーが要る件は、実機での確認を PR の「確認して欲しいポイント」に書く。
- Windows の Bash ツールではバックスラッシュが減る(グローバルの CLAUDE.md「ツールの制約」)。PR の本文は `--body-file` で渡す。

## 実機確認待ち

どれも、別の OS ユーザーのアカウントがある Windows で行う。手順と期待する結果は、各 PR の「確認して欲しいポイント」にある。

- #91、#92:別のユーザーからの変更系と GET の API の要求が 403 になる。昇格した PowerShell からの更新スクリプトも動く。
- #88:別のユーザーが `C:\VOICEVOX\vv-engine\run.exe` に置いたものが起動しない。
- #94:別のユーザーがエンジンのポートを先に取ると、`/version` 以外の要求が届かない。
- #96:別のユーザーがポート 7591 を先に取ると、フックの本文が平文で届かない。
- #90:表、箇条書き、引用を含む普段の応答の読み上げが、これまでと変わらない。
